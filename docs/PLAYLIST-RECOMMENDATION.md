# 确认页歌单推荐语

确认页左侧展示可编辑歌单，右侧展示当前主持人肖像和中文推荐语。卡片自然撑高，不截断正文，也不设置内部滚动；短屏可滚动整页。

首次生成歌单及整单「重新推荐」后生成推荐语，纳入原有生成节目等待页的最后一步「撰写歌单推荐语」。只有推荐语状态为 ready 且正文非空，才展示歌单确认页；刷新页面也遵守这一条件。排序、单曲替换、批量替换、撤销及重做保留现有推荐语。推荐语独立于口播，不调用 TTS。已有本地草稿首次被读取时补建推荐语任务。

生成流程：

1. 从完整歌单中分散选取最多四位不同艺人的代表歌曲，通过现有 Exa 搜索及网页原文读取能力查证资料。每个代表曲目最多等待 120 秒，不要求每首歌曲都有来源，失败曲目不会丢弃其他曲目的有效资料。
2. 把完整歌单的歌名、艺人、专辑，以及已核验的事实、当前主持人和收听偏好交给已配置的大模型。不会发送歌曲音频链接或用户听歌历史。
3. 生成 200–300 个非空白字符、以中文为主的三段简短推荐语：整体听感，代表歌曲与艺人，推荐理由。具体背景和风格须由资料支持，不写曲序依赖、歌词、未经核实的故事。
4. 校验 JSON、长度、中文比例及事实引用 ID。格式不合格最多重写一次。引用资料可在卡片下方展开。
5. 没有可用资料、研究或写作失败、格式重写仍不合格，以及任一阶段超时后，使用已确定的歌名、艺人和已完成核验的资料组合成不超过 100 字的简版，不再次等待模型。没有核实资料时只用歌曲身份，不补写背景；仅展示实际采用资料的引用。部分歌曲缺资料不影响其他歌曲的资料和正常写作。取消或退出不会触发简版。

提示词位于 `src/server/playlist-recommendation.ts` 的 `PLAYLIST_RECOMMENDATION_PROMPT`。联网研究和文案生成总超时为 600 秒。初次生成和整单重荐都在歌曲确定、保存后立即启动推荐语任务，在等待页完成文案后展示确认页，不会因文案超时回滚新歌单。资料可用且正常未超时仍执行原有 200–300 字要求。推荐语和当前内存节目草稿采用相同生命周期，服务重启后不会恢复旧草稿。

验证：`node --import tsx --test tests/playlist-recommendation.test.ts`；服务接口回归覆盖初次生成、操作重放、整单重荐、排序及单曲/批量替换的触发次数。
