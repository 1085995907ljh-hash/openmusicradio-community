# AI 音乐电台整档口播

## 任务边界

本 Skill 负责一档节目从调研、布点到逐条写作、事实检查、整档编辑和最终锁稿的完整闭环。

输入至少包含：

- 已锁定顺序的歌单，含曲名、音乐人及可用的专辑和熟悉度信息。
- 口播频率 `low`、`medium` 或 `high`。
- 音乐氛围 `musicAtmosphere` 及其枚举 `scenePreset`：`late_night`、`study`、`workout`、`commute` 或 `party`。
- 调用方按实际时段提供的 `openingGreeting`，以及电台和主持人身份文字 `openingIdentity`；身份也可由调用方明确的电台名、主持人名构成。缺少这些信息时先补齐输入，不由模型猜测默认值。
- 可选的节目主题、主持人口吻设定、目标听众和近期节目口播。

**Out of scope：**不选歌、不改变曲序、不删除或补歌、不合成 TTS、不写节目摘要。调研只能服务当前口播，不能把资料笔记直接念给听众。

路由用例见 `evals/trigger_cases.json` 和 `evals/semantic_config.json`；它们不代替实际生成与试听验证。

## 整档流程

1. 按 [调研契约](references/research-contract.md) 对每首歌自主执行真实搜索和原文读取，不限定网站、搜索轮数或事实条数；根据已读材料决定补查与完成。保留逐曲查询、阅读、事实主体和原文证据记录。全部歌曲完成调研才能撰稿；查询失败、能力缺失或漏歌时阻塞，不能降级为报歌。完成必要补查后确实没有资料才允许简短介绍。按每个位置实际可用的内容判断资料量，不能以全局资料条数或存在网页来源代替判断。
2. 主持人读取 [写作方法](references/writing-method.md) 和 [撰稿契约](references/generator-contract.md)，确定全部口播位置及每段值得讲的一件事。规划阶段不写正文，不改变歌单顺序。
3. 按位置顺序一次写一条，读取当前事实和 `completedBreaks` 避免重复。每段交给监制按 [审核契约](references/reviewer-contract.md) 的 `fact_check` 阶段检查事实与节目位置硬伤。
4. 无硬伤的条目保存为内部检查点，加入 `completedBreaks` 后继续下一条；此时不是最终展示稿。硬伤只返修对应句子一次，再检查被修改的断言；仍有事实风险时删除风险句，保留可靠内容并检查删后衔接。必要时简短报歌；身份也无法确认时返回阻塞，不能编造可播稿。
5. 所有条目事实通过后，显式调用监制的 `show_edit` 阶段一次。监制通读整档，只为明显重复、绕口、资料堆砌等问题提供原句、替换句及原有事实 ID，不做新一轮逐条审美否决。
6. 应用可精确匹配、未引入新事实的局部编辑，复核受影响断言、节目位置与整档元数据限制。无问题的条目保持原样；不得开启第二轮整档审美审核。文风轻微不完美可以交付，硬伤未清除不可交付。
7. 最终整档锁稿后才展示 `breaks` 并交给语音链路。技术失败保留已完成检查点，由调用方按有界重试策略恢复当前阶段；重试耗尽返回明确失败。技术失败、事实风险和文风建议分开记录，不互相冒充，也不无限自动重试。

审核阶段和状态契约以 `references/reviewer-contract.md` 为准。调用方必须显式执行整档编辑、保存检查点并锁稿；仅替换提示词不会自动改变已有运行流程，不能把未执行的阶段报告为已完成。

## 布点规则

- 第一首歌前必须有开场口播。
- 最后一首歌前必须有结束提示口播。它仍然负责介绍最后一首，不写播完后的告别。
- 只有一首歌时只安排一条开场，同时包含最后一首提示。
- 中段候选位置是第 2 首至倒数第 2 首歌之前，曲序永远不变。
- 设中段候选数为 `M = max(歌数 - 2, 0)`。开场与最后一首提示不计入比例；`low` 取约 40%，`medium` 取约 60%，`high` 取约 80%，均四舍五入到最接近整数。比例是密度目标，可以围绕资料价值和节目节奏小幅调整；有候选但结果为 0 时，`low` 至少安排 1 个。
- 没有口播的歌曲间隔直接衔接下一首，不增加静音、等待提示或主持人占位。
- 中段位置先尽量均匀分布，再优先放在曲风或情绪明显变化、两首歌存在可靠关系、下一首需要更多背景，或资料价值较高的位置。
- 除高频或短歌单外，避免连续两首歌前都有口播。不能为了满足频率编造歌曲关系。

## 不可变规则

- 每个音乐事实必须能追溯到调研资料包中的来源 ID；证据不足就不写。
- 熟悉曲优先简短补一个有效信息，探索曲有具体材料时展开音乐人及作品来路约 20–30 秒。熟悉度影响内容取舍，实际材料量和节目节奏决定长度，不要求陌生歌曲必然长讲。
- 按普通话自然播报约每秒 3.5–4 个汉字估算篇幅；这是帮助取舍信息的尺度，不是机械截断线。
- 内容量决定长度，没有最低秒数或字数。只有元数据时，清楚报出歌手和歌名即可，少于 5 秒也有效；开场保留必要身份介绍。所有时长数字都只是自然播报的估算，不能用空话、减速、拖音、延长停顿或补静音凑时长。
- 歌曲本身缺少故事时，先使用已调研的歌手音乐背景、对应专辑的创作理念、风格或相关奖项；这些也没有可靠材料时才简短报歌。明确事实主体，不把歌手获奖说成歌曲获奖，不把专辑理念或风格推定为每首歌曲的创作意图或听感。
- 口播优先使用音乐人背景、长期风格、创作阶段、作品风格、经典成就和相关故事。作词、作曲和制作名单不是默认介绍材料，只有名单本身能解释作品来路、风格形成或经典地位时才提。
- 经典歌曲有材料时优先解释成就、流传故事或生涯意义；没有材料时允许简短报歌，不能只贴“经典”“耳熟能详”的标签。
- 开场必须使用输入提供的 `openingGreeting`，例如下午只能说“下午好”，不能自行猜成“晚上好”；随后交代电台和主持人身份，迅速进入第一首。中段不得重复问候。结尾第一句说明最后一首；单曲节目在开场问候与身份之后补此提示。
- 年份统一写阿拉伯数字加“年”，例如 `2017年`。禁止写 `二〇一七年`、`二零一七年` 这类中文数字年份，避免 TTS 把“零”读错。
- 中段可以承接上一首，但只有真实的曲风、情绪、创作者或节目关系才能建立连接。
- 专辑与单曲同名时不重复介绍专辑名。资料不足时只说已经确认的音乐人、曲名和少量背景。
- 专辑名和发行年份只是低优先级元数据，不能成为整档的重复主体。同一档最多两条口播只靠这类元数据补充信息，且“专辑”和“年份”各最多一次；其他资料不足的位置只简洁报出音乐人和歌名。“未知专辑”、`Unknown Album` 等占位值永远不播。
- 每段围绕一个值得听的信息，或完成必要的报歌动作。允许一句符合真实曲序的简短承接，不要求每句话增加新事实。自然感来自内容取舍和顺畅词序，不来自固定口头禅。
- 音乐氛围必须改变整档口播的句长、节奏、转场力度和措辞，但不能改变事实、编造歌曲情绪或降低信息密度。放松与派对必须仅凭文字就能听出差异。
- 方法是判断顺序，不是固定文案结构；示例只能校准，禁止批量套句式。
- 评论区、高赞评论、粉丝留言和无法核验的公众评价不进入事实资料包，也不得出现在口播中。

## 输出契约

内部位置规划：

```json
{
  "frequency": "low | medium | high",
  "placements": [
    {
      "id": "break-01",
      "beforeTrackIndex": 1,
      "type": "opening | middle | closing",
      "targetSeconds": 20,
      "reason": "为什么在这里插入口播"
    }
  ]
}
```

单条口播初稿或修改稿：

```json
{
  "break": {
      "id": "break-01",
      "beforeTrackIndex": 1,
      "type": "opening | middle | closing",
      "targetSeconds": 20,
      "text": "可直接播出的口播",
      "sourceIds": ["来源 ID"],
      "deliveryInstruction": "TTS 演绎指令"
  }
}
```

产品只展示最终组装的 `breaks`，按 `beforeTrackIndex` 排列。研究笔记、内部判断、布点理由、审核过程和资料不足说明都不展示给听众。

正常的简短报歌是有效内容选择，不等于失败。事实风险导致的降级只保留已确认内容，不默认添加年份或专辑；它仍须满足身份、节目位置和整档重复限制。文风问题不触发固定模板，技术失败不生成替代口播。
